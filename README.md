# OntoLens — визуализатор прикладных онтологий для экспертной валидации

Статическое одностраничное приложение: открывает Turtle-файл с диска, показывает
онтологию так, чтобы её мог проверять эксперт-предметник, не знающий OWL и SKOS,
и одновременно даёт автору онтологии список дефектов модели с числами.

Реализация по ТЗ «визуализатор прикладных онтологий для экспертной валидации
(OntoLens-KZ)», версия 1.2 от 20.09.2026.

**Состояние: релиз 1 по разделу 8 ТЗ.** Сделано: 5.1 загрузка и модель, 5.2 браузер
концептов, 5.3 карта «вы здесь» и семантический зум, 5.4 сбор замечаний со
скриптом `review2master.py`, 5.5 диагностика и метрики, 6 нефункциональные
требования, 7 профили, экспорт SVG фрагмента. Приёмка на реальных данных
(GeOnt-KZ.ttl, мастер-таблица) ещё не проводилась — файлы не переданы.
Релиз 2 (5.6–5.9, карта расхождений, инкрементальная раскладка, эвристики) не начат.
Подробности — в разделе «Соответствие ТЗ» ниже.

## Хранилище моделей на диске (3.1, 16.11.2026)

Стартовый экран открывает папку-хранилище (например, `D:\Prog\OntoLens_Files`) вместо отдельных файлов.

```
<хранилище>\OntoLensF_<НАПРАВЛЕНИЕ>\ГГММДД-<Имя>-vX.Y\   — распакованный пакет версии
    *.ttl, profile.json, METRICS.md, metrics.json, corpus\*.csv
    work\                                                — работа в OntoLens (пишет приложение)
        review-<эксперт>.json    оценки эксперта (формат ontolens-review/1 + вердикты по коллизиям)
        corpus-work.json         классы, свойства, аксиомы, формализации редактора корпуса
        ГГММДД-…                 выгрузки (CSV, MD, SVG, Turtle)
```

- Chrome, Edge: папка выбирается один раз (File System Access API), дескриптор хранится в IndexedDB; после перезапуска браузер просит одно подтверждение доступа.
- Firefox, Safari: папка выбирается через диалог выбора каталога, только чтение; работа остаётся в браузере.
- «Открыть» — все .ttl версии + profile.json; «Коллизии» — глоссарии из corpus\; «Отчёт» — METRICS.md.
- Оценки и работа редактора пишутся в work\ версии и читаются оттуда при открытии в любом браузере; свои оценки сливаются с черновиком браузера по времени, чужие видны автору в «Замечаниях».
- Нет своих оценок — предлагается перенос с предыдущей версии того же направления.
- Профиль: `neighbourhoodSkipProperties` — свойства, связи по которым не рисуются в окрестности термина; `languages` в виде `{required, optional}` тоже принимается.

Тест: `node tests/vault.mjs <папка-хранилища>` (OPFS вместо папки пользователя; восстановление дескриптора из IndexedDB в headless Chromium не проверяется — вкладка закрывается при чтении дескриптора, это ограничение среды).

## Запуск

Готовый файл — `dist/index.html`. Он самодостаточен: ни сети, ни установки,
ни сервера не нужно.

```
открыть dist/index.html двойным щелчком
```

Дальше — «Открыть .ttl» или перетащить файлы в окно. Можно открыть сразу
несколько файлов пакета (TBox, документы, SHACL) — они объединяются в один граф,
принадлежность триплета файлу сохраняется.

Параметры URL (работают при размещении на статическом хостинге):

| Параметр | Значение |
|---|---|
| `?src=путь.ttl` | загрузить онтологию по ссылке; можно повторить несколько раз |
| `?profile=профиль.json` | подключить профиль онтологии (раздел 7 ТЗ) |
| `?lang=ru\|kk\|en` | язык интерфейса |
| `?demo` | сразу открыть встроенный демонабор |

Горячие клавиши: `/` — поиск; `1`–`5` — оценка термина; `Ctrl+Enter` — сохранить
и перейти к следующему; `N` — следующий непроверенный; `M` — свернуть карту;
`d` — «Термины ↔ Диагностика»; `Esc` — вернуть обзор графа или закрыть окно;
`F1` или `?` — встроенная справка «Как пользоваться».

У всех кнопок и переключателей есть всплывающие подсказки: они появляются и при
наведении мыши, и при переходе на элемент с клавиатуры.

## Что видит эксперт

Левая панель — тематические блоки (`skos:Collection`) с числом терминов, либо
иерархия классов, либо список свойств. Поиск идёт по меткам на всех языках,
по `altLabel` и по определениям; казахские буквы приводятся к базовым (ә→а,
қ→к, і→и), поэтому термин находится и без точного набора диакритики. Флажок
«нестрогий поиск» добавляет поиск с опечатками.

Карточка термина: метки на трёх языках рядом, отсутствующая метка помечена
явно; определения на всех языках; происхождение метки показано человеческим
текстом («авторский перевод», «подтверждён источником»), а не именем свойства;
документ-источник — с кодом, названием, статусом и годом, если он описан в
графе, и с явным предупреждением, если провенанс задан строкой; родители, дети,
блок; SHACL-ограничение в человекочитаемом пересказе (`measuredValue ≤
permittedValue`). Технические сведения (IRI, типы, файлы) вынесены в правую
панель.

Граф окрестности: предки до корня, потомки на глубину 1–2, братья, документ,
SHACL-шейп; клик по узлу — переход. Кнопка «SVG» выгружает именно этот фрагмент.

Семантический зум (5.3): масштаб меняет содержание узла. Дальний план — только
форма и цвет типа (термин — круг, структурный класс — квадрат, внешний — ромб,
документ — пунктирный прямоугольник); средний — метка до 24 символов; ближний —
карточка с метками на трёх языках, кодом документа, значками SHACL и оценки;
максимальный — ещё и начало определения. Пороги (0,4 / 0,8 / 1,6) задаются в
профиле, смена уровня идёт через прозрачность. При выборе термина вид за ~370 мс
приближается к нему до ближнего плана; `Esc` возвращает прежний масштаб.

Карта онтологии (5.3) — окно в углу графа. Острова — тематические блоки (при их
отсутствии — ветви верхнего уровня), отдельный остров — структурные классы.
На карте: отметка «вы здесь», путь до корня, след из последних посещённых
терминов (клик — вернуться), рамка той части острова, что видна в основном виде.
Три уровня детализации по масштабу карты: только острова с прогрессом → точки
терминов → точки с подписями. Проверенные термины окрашены по оценке,
непроверенные белые — видно, где остались пятна. Колесо — масштаб, перетаскивание —
сдвиг, клик по острову — приблизиться к нему, двойной щелчок — полный вид.
Кнопки в заголовке: сохранить раскладку в `map-layout.json`, сменить угол,
развернуть на половину экрана, свернуть (`M`). Положение и состояние окна
запоминаются.

Раскладка карты детерминирована: зависит только от IRI и порядка коллекций, не от
языка, выбранного термина или оценок. Считается один раз на версию онтологии
(хэш файлов) и кэшируется в браузере; `map-layout.json`, приложенный к онтологии
(перетаскиванием или `?layout=`), имеет приоритет — так у всех экспертов «вы
здесь» оказывается в одном месте.

## Оценка термина (5.4)

Правая панель «Ваша оценка»: верно / исправить / удалить / не мой домен / дубль
термина (с выбором, какого). Поля: исправленное определение, исправленные метки
ru/kk/en (текущее значение — подсказкой в пустом поле), предлагаемый родитель
(выбор из списка классов), комментарий. Правила из регламента: слово-подтверждение
(«дұрыс», «верно», «ок»…) в поле исправления не сохраняется — для этого есть
оценка «Верно»; значение, совпадающее с текущим, сохраняется как пустое.

Оценки хранятся в браузере (по хэшу онтологии) и переживают перезагрузку; если
браузер не даёт сохранять, панель прямо об этом говорит. Счётчик «N / M» в шапке
и полосы прогресса у блоков показывают пройденное. Внизу панели — выгрузка
`review-<эксперт>-<ГГММДД>.csv` и `.json`. Имя эксперта в имени файла
транслитерируется: кириллица в имени скачиваемого файла в части браузеров
заменяется на «download».

Столбцы CSV: `id; verdict; def_ru_fixed; label_kk_fixed; parent_proposed; comment;
ts` — контракт регламента (раздел 7), дальше `iri; label_ru; label_ru_fixed;
label_en_fixed; duplicate_of; expert`. Оценка пишется словом листа 3 книги
(«Верно», «Исправить», «Удалить», «Не мой домен», «Дубль термина»).

Вкладка «Замечания» (автор): загрузка файлов нескольких экспертов, таблица
оценок по терминам с фильтрами «с замечаниями / расхождения / не проверены»,
полное согласие и κ Флейса по терминам, оценённым всеми, выгрузка сводки CSV.
Оценки экспертов видны и в карточке термина, в дереве — значок числа замечаний.

## Влив замечаний в мастер-таблицу

```bash
python3 review2master.py build/master.xlsx review-*.csv            # → build/master.reviewed.xlsx
python3 review2master.py build/master.xlsx review-*.csv --dry-run  # только отчёт
python3 review2master.py build/master.xlsx review-*.csv --in-place # поверх, с резервной копией
```

Что делает: на каждого эксперта — столбец `verdict_<эксперт>`; `def_ru_fixed` →
`def_ru` и `def_ru_revised = TRUE`; `label_*_fixed` → `label_*`; `parent_proposed` →
`parent`; комментарий, «удалить» и «дубль» дописываются в `notes` (статус термина
меняет только автор). Если два эксперта предлагают для одной ячейки разное,
ячейка не меняется, случай уходит в раздел «Конфликты» отчёта. Слова-подтверждения
не вливаются. Повторный запуск с теми же файлами ничего не дублирует. Отчёт —
`<результат>.review-report.md`. Нужен `openpyxl`.

## Что видит автор

Вкладка «Диагностика»: 38 проверок по разделу 5.5 ТЗ, сгруппированных по
категориям (структура, метки и языки, определения, провенанс, свойства, внешние
ссылки, SHACL). У каждой — счётчик, объяснение «почему это важно» и список
сущностей с переходом на карточку. Правая панель — метрики файла; если в
профиле заданы целевые значения, рядом показывается «цель — факт».

Экспорт: `METRICS.md` (таблица показателей и сводка проверок) и CSV отчёта о
дефектах со всеми найденными сущностями. Имена файлов начинаются с даты в
формате ГГММДД.

## Профиль онтологии (раздел 7 ТЗ)

`profiles/*.profile.json` задаёт: требуемые языки, свойства меток, определений,
провенанса, аннотаций-пометок и их человекочитаемые подписи, префиксы внешних
онтологий, список структурных классов, минимальную длину определения, целевые
метрики. В поставке два профиля:

- `profiles/geodeticont-kz.profile.json` — пакет строительной геодезии
  (SKOS-слой, 27 структурных классов по разделу 4.2 задания v2.2, объявленный
  корень `GeodeticEntity`, целевые метрики 119/16/18/13/6; мосты считаются по
  всем внешним неймспейсам: 4 IFC + 2 GeoSPARQL);
- `profiles/geont-kz.profile.json` — онтология-предшественник по геотехнике
  (`rdfs:label`/`rdfs:comment` вместо SKOS).

Профиль подключается параметром `?profile=` или просто перетаскиванием
`.json` вместе с `.ttl`.

## Доступность и устойчивость

- Аудит axe-core по WCAG 2.1 AA на шести экранах — ноль нарушений. Для этого
  серый вспомогательный текст мокапа `#8A867D` затемнён до `#6B675E`: исходный
  давал контраст 3,5:1 при требуемых 4,5:1.
- Дерево терминов проходится с клавиатуры: ↑↓, → раскрыть, ← свернуть или к
  родителю, Enter — открыть карточку.
- Файл с синтаксической ошибкой не загружается целиком (как и в rdflib), но это
  больше не тихо: баннер под шапкой называет файл и строку, та же запись есть в
  диагностике в группе «Файлы».
- Метрики и проверки считаются по именованным классам основного неймспейса
  (`…#`), как в контрольном листе приёмки; классы соседних неймспейсов пакета
  видны в интерфейсе и показаны отдельной строкой метрик.

## Отклонения от ТЗ (согласованы 20.09.2026)

**Раздел 6 называет Cytoscape.js + cytoscape-dagre + cytoscape.js-navigator.
Использованы N3.js и собственный SVG-рендер с детерминированной послойной
раскладкой.** Причины: узлы графа должны быть карточками с метками на трёх
языках, кодом документа и значками — в Cytoscape это делается растровыми
подложками; экспорт SVG с редактируемым текстом в Cytoscape требует
дополнительного плагина, а при рендере в DOM получается сам собой;
клавиатурная навигация по узлам (раздел 6) в canvas-рендере пишется вручную.
Размер бандла — около 550 КБ против ориентировочных 1,5–2 МБ. Карта из раздела 5.3, ради которой назывался `cytoscape.js-navigator`, сделана на том же рендере: растровый слой на canvas плюс SVG-слой с отметкой и рамкой.

**Тестовые данные синтетические.** Приложения раздела 10 (GeOnt-KZ.ttl, пакет
GeodeticOnt-KZ, `build/master.xlsx`) не переданы. Вместо них сгенерированы два
набора, воспроизводящие структуру и типы дефектов: `data/demo-geodeticont-kz.ttl`
(119 терминов, 16 блоков с размерами по таблице 3 статьи, паннинг класс+концепт,
провенанс IRI, SHACL) и `data/demo-legacy-geont.ttl` (тег `kz`, классы-сироты,
множественные родители, провенанс литералом, свойства без домена и диапазона,
категориальные ошибки иерархии, `owl:imports`). **Определения в них вымышлены и
не являются нормативными.** Числа приёмки раздела 9 ТЗ на реальных данных не
воспроизводились.

**Два счёта там, где их путают.** «Классы без родителя» и «классы без метки»
показываются по именованным классам неймспейса онтологии; рядом — тот же счёт по
всем `owl:Class`, включая анонимные выражения и внешние IRI. Недопустимый тег
`kz` — по всем литералам графа; рядом — только в метках. Объявленные корни
(`rootClasses` в профиле) в «классы без родителя» не попадают.

**Рамка на карте.** Основной вид — окрестность термина, а не участок карты, поэтому
рамка показывает, какие узлы острова текущего термина видны в основном виде.
Перетаскивание рамки переводит на ближайший к её центру термин — это и есть
«панорамирование основного вида» в понимании ТЗ.

## Известные ограничения

- Ризонера нет; выведенная иерархия не показывается (по ТЗ — только через
  приложенный `*-inferred.ttl`, это пока не реализовано).
- Проверка «шейп ссылается на несуществующее свойство» обходит анонимные узлы
  на глубину не более 8 уровней.
- Граф окрестности показывает до 60 узлов; остальные свёрнуты в узел «+N»,
  клик по нему добавляет ещё 60.
- Множественное наследование в дереве иерархии показывается под каждым
  родителем, то есть один класс может встретиться в дереве несколько раз.
- Прогон выполнен в Chromium. Firefox и Safari не проверялись: в среде сборки
  есть только Chromium.
- Оценки эксперта живут в хранилище браузера до выгрузки. Очистка данных сайта
  или другой компьютер — и неэкспортированные оценки пропадут; панель об этом
  предупреждает, но общего хранилища нет до релиза 3.
- При изменении онтологии (другой хэш файлов) карта раскладывается заново.
  Оценки прежней версии не теряются: панель предлагает их перенести (по IRI, а
  переименованные термины — по `dcterms:identifier`); не найденные в новой
  версии термины перечисляются.
- На карте по умолчанию (240×180) подписи островов обрезаются; полные названия —
  во всплывающей подсказке и в развёрнутом режиме.
- В опубликованной по ссылке версии файлы сохраняются через подтверждение
  платформы (зритель видит имя файла и соглашается); если платформа сохранение
  не даёт, открывается окно с текстом для копирования. В этой среде проверен
  только локальный `index.html` — путь через платформу не проверялся.
- Сценарный тест с живым экспертом не проводился: 20 оценок в протоколе
  поставлены автоматом.
- Шрифты PT Sans / PT Serif / IBM Plex Mono подключаются, только если
  установлены в системе; иначе используются системные — это сознательный выбор
  ради требования «нет сетевых обращений».

# OntoLens — applied ontology viewer for expert validation (EN)

A single static HTML page that opens a Turtle file from disk and presents the
ontology in a form a domain expert can actually review — labels in three
languages, definitions, source document, hierarchy — while giving the ontology
author a numbered list of model defects.

**Status: core of release 1.** Implemented: file loading and internal model,
concept browser with a local neighbourhood graph, 38 quality checks with
metrics, ontology profiles, SVG fragment export, ru/kk/en interface, offline
operation from `file://`. Not implemented yet: the ontology map with semantic
zoom, the expert review panel, version diff, SPARQL, public page.

Build: `npm install && node build/make_bundle.mjs` → `dist/index.html`.
Tests: `node tests/run.mjs`, acceptance protocol in `tests/PROTOCOL.md`.

Test data shipped with the tool is **synthetic**: definitions are invented and
carry no normative force. The real GeOnt-KZ and GeodeticOnt-KZ packages were not
available, so the acceptance figures of the specification were not reproduced.

Deviation from the specification: the graph is rendered with an in-house
deterministic layered SVG renderer instead of Cytoscape.js + dagre, so that
nodes can be rich cards, SVG export keeps editable vector text, and keyboard
navigation works without extra code.
